# 0.2.23 实际复查与 EPUB 双页修复

本轮基线是公开正式版 0.2.23 (25)，主机安装版与虚拟机签名包的可执行文件
SHA-256 均为 `3e7bef5973e8934375553e2a09edf6782e4a275fb651e4d92dbeb8d00544e0af`。
源码基线为 `a44acce0653f85e5990a2a129a92dd15c694d348`。本记录不代替报告者确认。

## 确认的问题与修复

[#78](https://github.com/Ares-X/Sumra/issues/78) 从调查升级为实际 AppKit/MuPDF
渲染复现。五章真实 EPUB 的暂定页数 `[1,1,1,1,6]` 在后台变为 `[2,1,1,1,6]`，
阅读锚点始终为 `4:2:6`，但已绘制的左右页从第 4 章的 `2 + 3` 换成 `1 + 2`。
自然首次绘制路径和利用既有搜索计数开关控制发布时间的路径都保存了位图与日志。
这是实际阅读器画布，不是重写分页公式得到的模拟；自然路径使用离屏 AppKit host，
不能扩称为正式签名应用中已捕获到同一时序的真人可见动画。

修复在现有 ReaderState / PageRows / Pages 所有者完成：后台页数发布保留当前
双页的源起点，显示、相邻翻页、跨章预备、下一页预测与缩放使用同一配对相位。
实际字体重排、阅读模式、封面或文档变化重新建立配对。首页仍可懒分页，未增加
全书首屏前计数、渲染缓存、定时器或新依赖。封面保持独立；配对相位变化时书前
可能有额外单页，前后遍历不重复也不遗漏页面。

## 本轮验证

| 范围 | 结果与证据边界 |
| --- | --- |
| 相关代码回归 | 最终 51 个不同用例通过，0 失败、0 跳过。包含真实双页绘制后后台计数、封面开/关、同章及跨章前后翻页、字体重排提交、章节位置、懒加载、模式切换与缩放锚点。最初缺少环境变量而跳过的 3 个原始样本用例，已指定现有 Alice、格式样本及报告者 EPUB 后补跑通过。 |
| 视觉对照 | 未修改的实际 AppKit reader 自然路径有 `2+3 → 1+2` 的前后位图；修复后对应实际画布保持 `2+3 → 2+3`，源位置不变。 |
| 正式版 TXT / 标签 | 虚拟机真实打开 TXT；目录开关、620 点窄窗口与 1060 点宽窗口重排、浮动控件全屏进入/退出均实际观察。右页取得焦点后方向键使两页同向滚动。新标签取消保持原文档；选公共 PDF 后形成两个标签，关闭它回到原 TXT，顶栏正常。 |
