## PDF forms and accessibility

One MuPDF choice-field owner now handles GUI option indices, export arrays and
JavaScript assignments. It writes `/V` and ordered `/I` on the shared named
field, runs commit keystroke/validation rejection and dependent calculations, and
uses the existing journal. `Field.value` can assign string arrays;
`currentValueIndices` reads or assigns selected indices. Scalar paths retain
scalar conversion. MuJS exceptions release temporary PDF objects, including
throwing array getters and string conversion.

The native editor submits list indices, so two rows with equal export values
retain their distinct labels and identity. Regression coverage switches the
second row of single/multiple lists with duplicate exports, checks both shared
widgets, undo/redo, save/close/reopen and independently reads saved `/I` through
CoreGraphics. The initial integrated test exposed a write to temporary annotation
local xrefs; the fix writes persistent field values through the document journal.

Saved choice appearances use the same selected-index owner. A combo with
duplicate exports now draws the selected label; lists read inherited options and
`/TI`, draw only visible rows, and retain distinct selected background/text
colors. The existing MuPDF border, rotation, clipping and text writer are reused.
Independent CGPDF stream inspection and CoreGraphics rendering of the saved
appearance streams cover selected/cleared rows, undo, save and reopen. This
closes the reproduced blank inherited-list appearance and incorrect duplicate
label in the saved PDF.

PDFKit's normal Widget drawing rebuilt its own UI for this generated sample,
showing the first duplicate-export label and ignoring `/TI` and the authored
selection colors. The independent appearance test therefore draws the original
saved Form XObjects with CoreGraphics, retaining their resources and bytes.
PDFKit's Widget behavior remains an external-reader interoperability limitation;
correct saved `/V`, `/I` and appearances do not establish identical Widget UI in
every reader.

Virtual AppKit accessibility controls expose the painted fields and activate the
same native input path. Checkbox/radio roles, field labels, selected display
labels, permissions, read-only status, screen frames and password redaction are
passed through the Objective-C accessibility boundary. The active native input
replaces its virtual control. Tab/Shift-Tab from an editable PDF page enters the
first/last text or choice field and keeps the existing same-page traversal.

Bulk selection replacement does not represent an individual list gesture:
`changeEx` is empty, and noncommit gesture events are not invented. Multi-value
commit/validation event values are empty; a script cannot replace the committed
selection by assigning a scalar event value. This is targeted compatibility,
not complete Acrobat JavaScript or AcroForm support.

## EPUB search

The existing request cookie now reaches parsed and laid-out candidate walks and
the native matching loops. Production Swift uses that cookie directly instead of
calling a Swift cancellation closure for each flow character. Callback-only
native consumers retain their existing cancellation path.

The previous Python timing harness made approximately 71.9 million Python
cancellation calls on B10. Its roughly 30-second observation is not an app/native
latency measurement. A C callback measured 20.992 seconds; a Swift `-Osize`
`Task.isCancelled` bridge measured 20.980 seconds, and the cookie path 20.178
seconds. All returned 54 hits with identical offsets, source anchors and highlight
fragments. One pair does not establish a causal speedup; eliminating the repeated
language crossings is the verified structural change.

Request-cookie cancellation in an already parsed largest chapter returned about
0.028 ms after cancellation; callback mode returned about 0.039 ms in that probe.
Subsequent search, bounds and close recovered. Parsing/layout and uncanceled glyph
extraction can still occupy the actor for hundreds of milliseconds. These native
boundaries do not establish visible UI latency.

The natural-page candidate also retains unrelated basic-Han characters as
barriers for pure basic-Han queries. Previously deleting every non-query
character made widely separated Han look adjacent, forcing unnecessary full
glyph extraction. The existing visible LTR laid-out walk, normalization and
Fitz matching remain the owner. Non-Han content is still treated conservatively;
fixed layouts and mixed-direction flows retain their existing behavior.

| Quiet native observation | Baseline | Han barriers |

| B10 complete count, 54 hits | 20.580 s | 11.577 s |
| B10 glyph search stage | 10.850 s | 1.945 s |
| B10 longest glyph-search call | 411.704 ms | 50.861 ms |

B22's separate product-cap run returned the same first 1,000 hits. Every match's
UTF-16 offsets, source anchors and geometry agreed, as did complete hit-page JSON
including text. Natural fixtures cover 39×8 exact/folded and word modes, long
barrier runs, overlap, zero-matrix Han, cross-flow/block text, generated/hidden/
transparent CSS and bidi. Ordinary candidate and cross-page harnesses also pass.
These are single-process observations, not a distribution or general speedup.
Parsing/layout still reached about 95/98 ms; complex non-Han text can still need
full glyph extraction. The previous rejected normalization experiment remains
removed.

The same `-Osize` Swift probe with the final Han candidate observed 11.619 s,
first native hit 18.056 ms, and the same 54-hit canonical result hash. The private
GUI first exposed `Searching… 1 matches`; while counting, Next Page reached
chapter 2 at 9.366 s. At 15.284 s it was still counting; by 29.510 s Find Next
showed `2 / 54` in chapter 3. This is an observed completion interval, not an
exact UI completion time or the native 11.619-second boundary.

Replacing a different active query (`Searching… 19 matches`) removed the old
results and exposed the new query's zero-match searching state within 1.416 s of
sending the action. Closing Find then allowed Right to reach chapter 4. This
validates actual paging, next-result, query replacement and close behavior;
it does not establish worst-case cancellation latency for every chapter.

Actual form GUI observation also confirmed native checkbox role/state, disabled
read-only fields and no password value. Pressing a list field exposed an AppKit
multi-select table; changing Alpha/Beta to Gamma and pressing Tab committed the
list and focused the name field. Save/reload retained Gamma and the checked box.
The password dialog exposed a labeled, initially focused secure input.
