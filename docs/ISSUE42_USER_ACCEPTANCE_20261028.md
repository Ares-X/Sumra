## 设计决定与明确边界

- 浮层是可选配置，默认关闭；保留维护者选择的克制留白。显示隐藏控制条只改变浮层，不推动正文。Medium/Wide 的上下总预算包含页内边距，不叠加两遍；Narrow 可以遮盖内容。
- EPUB、FB2、MOBI、AZW3、TXT、HTML/Markdown 使用各自重排路径。PDF/漫画保留固定页面的内容比例，使用适配页面及已有裁空白功能；本次去除不必要的控制条占位，不把固定版式强行重排。竖图两侧的比例留白与额外 UI 边距需要区分。
- New Tab 的原生工具栏 + 保持可发现，Tabs 菜单增加 New Tab。保留 macOS 的标签菜单；多个标签时禁用 Hide Tab Bar。没有严格照搬反馈者“+ 只首次显示、彻底删除系统菜单”的可选草图。
- 缺失封面的 EPUB 在此 Mac 的 Finder 仍为 Apple Books 通用图标；Sumra Quick Look 正常。反馈者此前明确接受这个边缘情况，不能宣称 Finder 图标已修好。
- 本轮真实 Quick Look 使用系统选择的已安装正式版扩展：Preview 来自 `/Applications/Sumra.app`，Thumbnail 来自现有正式版提取副本。没有改文件关联或扩展注册。候选扩展引擎另有通过的测试；这不等于系统已加载候选扩展字节。
- 全量搜索 7.84 s 是此前同一搜索源码与固定 CSS/视口的已记录结果，存在明确查询/排版边界，不代表任何大书均瞬时完成。当前轮没有重新测量性能。
- 个人验收与发布安装、Sparkle 更新、冷启动是不同阶段；本轮只交付本地候选个人验收，不提前对外宣称解决。

## 悬停事件坐标遗漏

再次诊断排除了状态同步与 mounted-host 失效，但最初把无窗口 mouseMoved 判断为无效输入的结论不准确。Apple 的 `NSEvent.locationInWindow` 文档明确允许 mouseMoved 没有关联窗口，此时该值是屏幕坐标。原 handler 的 `guard let source = event.window` 会忽略这种合法输入；当前修复在既有 owner 中将其转换到阅读窗口，保留 key-window、窗口内顶部区域和其他窗口排除逻辑，不加轮询或重试。新增行为回归在旧实现的顶部 reveal 断言处失败；修复后的整批和实际窗口验收另行记录。

验收工具尝试从 NSEvent 转成 CGEvent 并修改位置后，收到的局部坐标固定在窗口外，属于错误投递，已恢复直接 CGEvent 系统投递；该尝试不计为通过。普通窗口只因通知采样显示工具栏，也不能作为 mouseMoved 处理已通过的证据。

本轮一次有完整启动日志的冷启动已成功：file URL 在 launch 前入队，Home 连接后由同一 state 复用加载。此前两次 Home-only 没有启动交接日志，具体原因仍未知；不能将一次成功或第二次打开成功称为已修复该观察。当前启动源码没有为此增加延时、重试或补救路径。
