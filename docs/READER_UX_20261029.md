# Reader UI and interaction contract

This pass retains the chosen restrained floating-control style. Home, document
navigation and macOS window lifetime have distinct, predictable responsibilities.
The implementation uses the existing native window group as its document-tab
model. No hidden Home tabs or separate tab-navigation order are introduced.

## Screens and actions

| Step | Surface or action | Required result |
| --- | --- | --- |
| 1 | Home | An independent launch window with recent files and Open. Its fixed header has window controls, a title and Open, with 16-point side gutters. It has no reading overlay or document-tab row. |
| 2 | Open the first book | Reuse the empty Home window. Present the book with a single filename, a close target and Add Tab; the filename occupies the available document-control width. |
| 3 | Add Tab / Command-T / system tab-bar Add | Select files first. Confirm creates document tabs in the current group; Cancel leaves windows, reading position and selection unchanged. The saved default Open policy does not change this explicit action. |
| 4 | Multiple books | Tabs share the document strip while they fit. When crowded, scroll horizontally instead of shrinking the close targets or moving Add Tab. Reveal the selected document, retain colors and show full filenames in help text. |
| 5 | Switch documents | Only document windows participate. Update the selected tab and its book without relocating the control strip or changing the book viewport for hover. |
| 6 | Go Home | Activate an existing independent Home, or create one. Keep every open book and its reading position. Home never enters the document group. |
| 7 | Close a document or Home | Close only the requested window through the existing save/discard/cancel owner. Other books remain open. Closing the last reader leaves the macOS application running. |
| 8 | Reopen the running app from the Dock | Restore the existing selected reader, including a minimized window; create Home when no reader remains. Auxiliary system windows do not count as a reading window. |
| 9 | Narrow window | Combine the three reading-control groups into one compact row. Keep side gutters, middle filename truncation and reachable buttons. |
| 10 | Full screen, hover and system menus | Keep every button painted and clickable. Follow the originally identified native control container into its full-screen companion, including its first creation after the factory lookup changes. Do not move or repaginate the book as controls appear. |
| 11 | Always Hide | Keep reading tools and document tabs hidden. The top edge still reveals only the macOS window buttons, including an available exit from full screen. Presentation suppresses this reveal. |

## Visual and motion rules

- Preserve the selected 36-point reading-control capsules, restrained borders
  and shadows, existing themes and configurable page clearances.
- Use 16-point top and side gutters for reading controls. Keep the window
  buttons below the macOS sharing-indicator band; Home aligns its controls to
  that same row. Medium/Wide clearances include this inset once, at 54/62 points.
- Keep Add Tab in a fixed 24-point slot. Multi-document close targets are
  20 points; fitting document tabs share the remaining width, with a 120-point
  minimum before horizontal overflow. Home has no document close/Add controls.
- Retain the existing short opacity-based reveal and dismissal. Do not animate
  the window frame, book size or tab-strip position. Reduce Motion bypasses
  nonessential motion.
- Preserve the accepted bottom progress dimensions and equal inner padding.
  Top-header work must not change progress tracking or navigation completion.
- Read complete native document groups for switching, closing and persistence;
  system tab-bar visibility must not reduce the document model to one window.

## Acceptance evidence

The earlier signed candidate was rejected. Stable reading pixels and accessible
button labels did not establish painted or clickable full-screen controls. The
failed candidate and subsequent failed owner hypotheses remain failure evidence.

Acceptance of this contract requires fresh desktop-composite screenshots at
ordinary, narrow and full-screen sizes, inspection of those saved images, and
real pointer hits followed by the expected action. Repeated tab switches must
be followed by actual control use, not a screenshot-only check. The real file
chooser must exercise Confirm and Cancel. Close/reopen must be checked against
actual reader windows, independently of the application's running state.

Behavior tests protect routing, window ownership, closing and layout boundaries.
They do not replace real rendering, native chooser, menu, Dock or cold-launch
acceptance. Screenshots alone do not establish complete accessibility compliance.
The release remains paused until the changed flows pass those checks.
